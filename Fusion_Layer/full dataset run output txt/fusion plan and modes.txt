
# 1️⃣ Your current label structure

### 4-class primary labels


0 → RR (Real Video, Real Audio)
1 → FR (Fake Video, Real Audio)
2 → RF (Real Video, Fake Audio)
3 → FF (Fake Video, Fake Audio)


These represent **which modality is manipulated**.



### Binary labels for the video model

Your mapping:


RR → Real
RF → Real
FR → Fake
FF → Fake


Equivalent code:

```python
VIDEO_BINARY_MAP = {
    0: 0,  # RR -> Real
    1: 1,  # FR -> Fake
    2: 0,  # RF -> Real
    3: 1   # FF -> Fake
}
```

Interpretation:


Video authenticity only


So the model learns:


fake video → fake
real video → real


This is **exactly what a video detector should learn**.


# 2️⃣ Why RF must be labeled REAL for video model

RF means:


Real Video
Fake Audio


If you labeled RF as **fake**, your video model would learn:

fake audio → fake video


Which is **incorrect supervision**.

Your current mapping avoids this mistake.


# 3️⃣ When you train the audio model

You should flip the logic.

### Audio binary mapping
RR → Real
FR → Real
RF → Fake
FF → Fake


Example:

```python
AUDIO_BINARY_MAP = {
    0: 0,  # RR
    1: 0,  # FR
    2: 1,  # RF
    3: 1   # FF
}

Interpretation:


fake audio → fake
real audio → real




# 4️⃣ When you train the fusion model

You have two options.

### Option A (recommended)

Binary deepfake detection.

```

Code:

```python
FUSION_BINARY_MAP = {

This matches **real-world deepfake detection**.

### Option B

Keep full 4-class classification.

But this requires **more training data** and is less stable.



# 5️⃣ Recommended full pipeline

### Video model

Input: frames
Labels:
RR + RF → real

### Audio model


Input: spectrogram
Labels:
RR + FR → real

### Fusion model
Input:
video embedding
audio embedding

Label:
RR → real

# 7️⃣ One small improvement I would suggest

Right now your mapping is implicit.

It is cleaner to store it explicitly.

Example:

```python
VIDEO_BINARY_MAP = {0:0, 1:1, 2:0, 3:1}
AUDIO_BINARY_MAP = {0:0, 1:0, 2:1, 3:1}
FUSION_BINARY_MAP = {0:0, 1:1, 2:1, 3:1}
```

Then inside the dataset:

```python
label = VIDEO_BINARY_MAP[primary_label]
```

This makes your **pipeline much clearer and reproducible**.
